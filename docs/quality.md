# Статическое тестирование и доказательства качества

Статическое тестирование включает ревью требований и кода, линтеры, проверку типов и анализ зависимостей без выполнения сценария готовки. Автотесты pytest/Vitest/Playwright относятся к динамическому тестированию и учитываются отдельно.

## Подготовленные проверки

В `.github/workflows/quality.yml` настроены:

- Prettier: оформление Markdown, YAML, JSON и будущих файлов интерфейса;
- Ruff: статический анализ Python и проверка форматирования;
- `git diff --check`: ошибки пробелов в отслеживаемых файлах.

Проверки запускаются на push и pull request, также доступны вручную. Пока Python-кода нет, Ruff не проверяет продуктовые функции. Факт успешного запуска на GitHub подтверждается только конкретным выполнением Actions.

## Подключить вместе с кодом

- Backend: pytest, Hypothesis, проверка повреждённых планов, циклов и ресурсов; аудит зависимостей pip-audit.
- Frontend: ESLint, `tsc --noEmit`, Vitest/Testing Library; `npm audit` после фиксации зависимостей.
- Перед демо: сквозной сценарий в Playwright, включая ширину 360 px и восстановление сессии.

## Ревью второго участника

Проверяющий сверяет изменение с требованием F/N, граничные случаи, сообщения ошибок, направление зависимостей и отсутствие секретов. Для ядра отдельно проверяются занятость человека и оборудования, зависимости, сохранность уже начатой работы и независимость валидатора.

## Что показывать преподавателю

1. Собственные коммиты каждого участника с реальными изменениями программного кода.
2. Pull request с обсуждением и исправлениями после ревью.
3. Запуск Actions на конкретном коммите и его результаты.
4. Описание использования ИИ и проверки человеком в pull request, если ИИ использовался.

Настройка репозитория и документация не выдаются за реализацию MVP или программный вклад всех троих. Результаты будущих проверок добавляются только после их выполнения.
