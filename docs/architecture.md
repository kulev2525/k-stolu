# Архитектура

Источник: `Arhitektura_K_stolu.docx`, решение команды от 29 октября 2026 года. Описывает целевое устройство; программная реализация в этом репозитории ещё отсутствует.

## Границы и слои

- React + TypeScript + Vite: интерфейс, состояние через Context/useReducer, профиль кухни и снимок готовки в localStorage.
- Python 3.12 + FastAPI: один модульный монолит; направление зависимостей API → приложение → доменное ядро. Ядро не зависит от FastAPI и базы.
- SQLite + SQLAlchemy: каталог и обезличенная обратная связь. Рецепты в YAML проходят валидацию перед загрузкой.
- Планируемое развёртывание: один Docker-образ с API и собранным интерфейсом на одном домене, HTTPS через Caddy.

## API

| Метод | Адрес               | Назначение                                 |
| ----- | ------------------- | ------------------------------------------ |
| GET   | `/api/recipes?q=`   | Каталог и поиск                            |
| POST  | `/api/plans`        | Создание общего плана                      |
| POST  | `/api/plans/recalc` | Пересчёт по снимку текущей готовки         |
| POST  | `/api/feedback`     | Необязательная обезличенная обратная связь |

## Ядро

`EquipmentChecker` проверяет наличие оборудования. `Scheduler` размещает шаги с учётом человека, оборудования и зависимостей. Несколько эвристических порядков сравниваются по разрыву готовности блюд и общей длительности; математическая оптимальность не обещается.

`PlanValidator` независимо проверяет полноту шагов, длительности, зависимости, пересечения активных действий и занятость оборудования. Недопустимый план не показывается пользователю.

`Recalculator` фиксирует завершённые и начатые шаги и перепланирует будущие. Истечение таймера без подтверждения не освобождает ресурс.

## Данные и ошибки

Длительности хранятся в секундах, отметки событий — ISO с часовым поясом. Снимок имеет версию схемы и содержит копию рецептов. Ошибки API имеют поля `code`, `message`, `details`; сообщение пользователю — на русском, без трассировки.

Отсутствующее оборудование и невозможность построить план — разные ошибки. Ввод ограничивается на сервере; пользовательские строки выводятся с экранированием. Регистрация и внешние сервисы для работы MVP не предусмотрены.
